# CloudForenX — Digital Evidence Integrity & Chain of Custody (Research Demo)

**Developer / paper author:** Parikshit Gulia, B.Tech CSE, SGT University, Gurugram.

**Research paper:** [Bridging the awareness-practice gap in digital evidence handling: A survey and prototype-based study on integrity verification and chain of custody](https://doi.org/10.33545/26633582.2026.v8.i2b.292) (International Journal of Engineering in Computer Science, 2026, 8(2), 163–174).

This is a **reconstructed** Streamlit application designed to match the six-page UI/workflow shown in the publication (Figures 6–11). It is NOT the original deleted source code. Its extended features below are new implementation details, not claims about the original published prototype.

## Run on Windows / VS Code

Open Command Prompt in the folder containing `app.py`, then:

```cmd
py -m pip install -r requirements.txt
py -m streamlit run app.py
```

Open http://localhost:8501 if it doesn't open automatically.

## Pages (same as published screenshots)

1. **Upload Evidence**: Case ID, evidence name, type, collector, sample file; SHA-256 generated automatically; file saved in a temporary per-session folder; record stored in a per-session SQLite database.
2. **Dashboard**: Search/filter by case/name/collector; evidence table, hash, type, sample-file export, CSV export. This is also the **cloud-repository simulation**, not external cloud hosting.
3. **Verify Integrity**: Select stored record, upload comparison file, hash comparison, match or mismatch status, custody event logged.
4. **Chain of Custody**: Logged UTC timestamps, case ID, collector, action, hash and status. View/export CSV; optional simulated manual handling actions.
5. **Guidance**: Basic evidence-handling advice, Indian legal context and official Indian cyber-help/reporting links.
6. **Awareness Quiz**: Five-question training quiz with score and feedback. Not a validated behaviour assessment.

### Mapping to the originally planned eight capabilities

- Secure upload with SHA-256 → **Upload Evidence** (not secure/authenticated infrastructure).
- Custody log → **Chain of Custody**.
- Evidence classification → **Evidence Type** on **Upload Evidence**, stored with record.
- Legal handling guidance → **Guidance**.
- Indian cyber-help links → **Guidance**.
- Integrity checker → **Verify Integrity**.
- Cloud-storage simulation → **Dashboard** (SQLite + temporary server files, **not** actual cloud object storage).
- Awareness assessment → **Awareness Quiz**.

## Deployment: Streamlit Community Cloud

Upload the *contents of this folder* to a GitHub repository. In [Streamlit Community Cloud](https://share.streamlit.io/), choose **Create app → Existing repo → select repo → `app.py` → Deploy**. Requirements are detected from `requirements.txt`.

**Important:** This public demo uses *isolated, temporary per-session* SQLite and file storage. Records can disappear on restart/session expiration. There is no account authentication or role-based access control. Do not upload genuine evidence or confidential/personal files. A persistent production system would require authentication, authorization, encryption, secure storage, independently auditable logging and legal/forensic validation.

## Originality and scope

The survey in the published paper had **38 respondents**. Those results are **not generated by this application**; the quiz is a separate demonstration feature. This reconstructed version supports SHA-256 checks and structured logging, but **does not establish court admissibility**, prevent tampering or provide immutable custody logs.
